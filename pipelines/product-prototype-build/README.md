# Product Prototype Build

Интерактивный пакет AFM формата v2. Пользователь подтверждает сценарии, выбирает визуальное направление, комментирует работающий прототип и утверждает комплект для передачи разработчику.

## Запуск

Нужны AFM с поддержкой пакетов v2, Docker autoShim, управляемый браузер, Python 3, авторизованный Codex с доступом к `gpt-6.1-sol` и переменная окружения `CLAUDE_CODE_OAUTH_TOKEN` с доступом к `claude-sonnet-5-5`. AFM Desktop открывает управляемый браузер во вкладке. При запуске из CLI используется Chrome.

В рабочей папке продукта проверьте и запустите пакет версии `0.3.1` с Git-тега `v2.5.1`.

```sh
pipeline='github.com/akopichin/afm-pipelines//pipelines/product-prototype-build@v2.5.1'
AFM_COLLABORATION=1 afm pipelines inspect "$pipeline"
AFM_COLLABORATION=1 afm run --pipeline "$pipeline"
```

Для локальной копии задайте абсолютный путь к пакету в переменной `pipeline`.

Для возобновления повторите команду с тем же источником из той же рабочей папки. Чтобы изменить модель или reasoning, скопируйте [options.example.yaml](options.example.yaml), отредактируйте нужные роли и передайте путь к файлу.

```sh
AFM_COLLABORATION=1 afm run --pipeline "$pipeline" --pipeline-options "$HOME/.afm/prototype-options.yaml"
```

## Работа с прототипом

1. Аналитик согласует задачу и проверяемые сценарии. Если доступны целевые пользователи или материалы исследований, он разбирает конкретные случаи их работы. В бриф попадают источники выводов и гипотезы, которые ещё предстоит проверить.
2. Дизайнер прогоняет бриф через локальный UI/UX Pro Max, разбирает открытые референсы и записывает применимые решения в `design.md`. По методу Oil UI он показывает рядом 2–3 концепта ключевого экрана с одинаковыми данными, разной композицией и гипотезой для каждого. Можно выбрать вариант, объединить детали или запросить ещё одну итерацию. [UI/UX Pro Max](skills/ui-ux-pro-max/UPSTREAM.md) · [Oil UI](https://github.com/oil-oil/oil-ui)
3. Прототипист собирает один HTML-файл с правдоподобными данными, работающими действиями и способом вызвать релевантные пустые, загрузочные и ошибочные состояния. Перед показом проверяет сборку в CDP и полирует типографику, слои и состояния контролов. В режиме «Разметка» протяните стрелку, добавьте комментарий, нажмите «Добавить». Кнопка «Отправить» передаст пачку замечаний с координатами, снимками и адресом экрана. Для обычных кликов выключите разметку. После исправлений нажмите «Утвердить версию». [High-Craft HTML Prototyping](skills/high-craft-html-prototyping/SKILL.md) · [Полировка по навыкам Jakub Krehel](skills/product-interface-polish/SKILL.md)
4. В live-qa проверяющий повторяет задания в отдельном CDP-сеансе. Функциональный ревьюер сверяет результаты сценариев, а независимый дизайн-критик оценивает снимки широкого и узкого экранов и сложных состояний. Блокирующие замечания запускают исправление, повторную проверку и утверждение новой ревизии. [plugin87](https://github.com/plugin87/ux-ui-agent-skills)
5. Писатель показывает две спецификации и две HTML-версии. После утверждения и успешной проверки AFM сохраняет комплект в папке `delivery/` в корне проекта. В ней находятся `behavior.md`, `design-system.md`, `prototype/index.html`, `design-system/index.html`, отчёты и материалы проверки. Для просмотра HTML требуется доступ к CDN.

Если `delivery/` уже существует, новый комплект сохраняется в `delivery/<run-id>/`. Ссылки из копий отчётов на материалы предыдущих этапов ведут в журнал запуска в `.afm/runs/`. Контрольные суммы относятся к утверждённым файлам в журнале запуска.

Авторы работают на `gpt-6.1-sol`. Аналитик, дизайнер и frontend-прототипист используют `high`, писатель и помощник для косметических правок используют `medium`. Живой QA и функциональные проверки выполняет `claude-sonnet-5-5` с `high`. Для отдельного визуального ревью Sonnet использует `medium`.

В пакет входят Anthropic Frontend Design и навык `product-visual-design` с разбором референсов и критериями визуальной критики по Impeccable. Дизайнер проверяет свёрстанные концепты через CDP и использует доступный imagegen для иллюстраций и фотографий, если они нужны по брифу. Если внешние галереи недоступны, он продолжает на доступных материалах и указывает это в `design.md`. [Anthropic Frontend Design](skills/frontend-design/UPSTREAM.md) · [Impeccable](https://impeccable.style/docs/)
