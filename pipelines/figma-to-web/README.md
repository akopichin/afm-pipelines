# Figma → Web

Пакет AFM v2 переносит выбранные страницы и состояния Figma в статический HTML. На этапе вёрстки используется [frontend-design](skills/frontend-design/UPSTREAM.md). Источник визуальных решений и значений CSS — согласованные фреймы Figma.

## Запуск

Нужны AFM с поддержкой пакетов v2, Docker autoShim, Agent Mesh, Python 3, авторизованный Codex и управляемый Chrome. Для ручного входа и приёмки нужен видимый браузер (`browser.headless: false` в AFM). Пакет использует уже подключённый Figma MCP, когда он доступен в окружении запуска Codex. В Docker доступ через MCP зависит от конфигурации и авторизации Codex внутри контейнера. Если MCP не открывает макет, агент открывает его в управляемом Chrome и ждёт, пока вы войдёте.

Выполните в папке, куда нужно сохранить HTML. Укажите абсолютный путь к пакету и свою ссылку Figma.

```sh
pipeline=/absolute/path/to/afm-pipelines/pipelines/figma-to-web
afm pipelines inspect "$pipeline"
afm run --pipeline "$pipeline" --task 'Макет: https://www.figma.com/design/…?node-id=…'
```

Можно запустить без `--task` и дать ссылку в диалоге AFM. Если есть только экспорт фреймов, положите изображения в папку запуска и передайте агенту пути и исходные размеры. При возобновлении используйте тот же путь и ту же рабочую папку, опустив `--task`.

## Что происходит в прогоне

Во время любой агентной стадии можно написать её агенту в чате стадии. Формальные вопросы и подтверждения появляются в диалоге AFM. Финальный экспорт выполняется скриптом после утверждения версии.

1. Агент открывает Figma и при необходимости ждёт входа. После открытия уточняет страницы, состояния, адаптивность и интерактивность. Вы подтверждаете его пересказ в диалоге AFM.
2. Агент сохраняет эталоны и измерения выбранных фреймов, затем собирает HTML, CSS и нужные для работы страницы ассеты и скрипты.
3. Два независимых QA-агента работают в отдельных стадиях с CDP. Первый прокликивает сценарии, второй сравнивает снимки и параметры Figma с фактическими размерами и CSS в Chrome. Замечания исправляются и перепроверяются перед показом.
4. Вы прокликиваете прототип в браузере и оставляете замечания в диалоге AFM. После правок агент снова открывает актуальную сборку. Кнопка «Утверждаю версию …» относится к файлам показанной версии.
5. AFM сохраняет утверждённые файлы в `figma-to-web-output/<run-id>/` в папке запуска. В комплекте есть `index.html`, дополнительные HTML-страницы при необходимости, стили и ассеты. Комплект можно обслуживать обычным статическим HTTP-сервером. Бриф, эталоны и отчёты QA остаются в журнале AFM.

Все роли используют Codex `gpt-6.1-sol`. Для функционального QA используется reasoning `medium`, для остальных ролей — `high`. Модели можно переопределить через стандартный параметр AFM `--pipeline-options`.
